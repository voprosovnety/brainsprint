# V3 consumer interface

V3 is append-only `resources/funnel/brainsprint-v3.json` (schema_version integer 3). Its semantic screen inventory and local artwork paths are in `v3-content-manifest.json`. The ordered 58 entries preserve the reference positions; the two final entries are alternatives. Only schema 3 is supported. Publication uses the existing content hash seeder; merely editing files neither publishes nor migrates data.

Reuse bootstrap/start/show/complete/events/privacy endpoints and existing session, CSRF, locking, ownership, limits and no-store controls. Bootstrap returns `experiment: null` and `restart_required: false` for a supported visitor; no landing or assignment is created. Supported runs take precedence over the latest configuration. Unsupported saved runs use the retirement/deletion flow in [the consumer contract](README.md). First-touch attribution still initializes once. Frontend types: `apps/web/src/lib/v3.ts`.

Completion remains exactly `{answer: ...}`. No transition assertions or extra keys are accepted. Text/image choices and scales use `{choice: configuredOptionId}`. Intro, reveal, interstitial, confirmation, processing without prompts and final use `{acknowledged: true}`. Report preparation uses exactly `{focus: "yes"|"no", practice: "yes"|"no"}`. Email uses `{email: null|string}` (optional skip; valid email up to 254 characters). Paywall uses exactly `{offer_id: "report-intro-v3", acknowledged: true}`. Upsell uses exactly `{decision: "accept"|"decline"}`; accept follows `next`, decline follows `decline_next`. Final acknowledgement goes to `done`. All other transitions follow `next`. A confirmed canonical answer is immutable and identical retries return the current state. Required screens cannot be skipped. The server does not assess correctness or enforce presentation animation duration.

V3 run responses add `started_at` (UTC ISO), `teaser` (null until confirmation, then title/summary/section headings only) and `commerce: {deadline: UTC ISO|null, unlocked: boolean, upsell: "accept"|"decline"|null}`. `result` is null before simulated unlock, then an owner-only `illustrative_sample` with title, summary, disclaimer and sections `{title,body,practice}`. Store the generated report and commerce in the existing private result JSON; never serialize the private envelope. Generate once on confirmation independently of answers. Set a five-minute deadline once on transition into paywall. Expiry leaves the $0.99 demonstration accessible with an expired display; refresh never resets it. Unlock is a transactional acknowledged mock offer, never a payment. Do not accept financial fields or invoke a provider. Upsell decision persists through immutable answers. Final completion is distinct from unlock.

V3 events use new names where semantics differ: server `quiz_confirmed_v3`, `processing_completed_v3`, `mock_unlocked_v3`, `upsell_decided_v3`, `funnel_completed_v3`; `funnel_started` and `step_completed` retain their meanings. Actual client exposures: `step_viewed`, `paywall_viewed_v3`, `checkout_viewed_v3`, `report_viewed_v3`. Paywall view requires the paywall screen; checkout view is sent only when its checkout is visible; report view requires an unlocked final screen. Their semantic keys include event name, run and screen. Never emit purchase/revenue events, include email in analytics, or interpret locked preview as report access. Shared aggregates include only runs pinned to schema 3 and expose these stage semantics at the top level.

All data lives in the existing session-owned run and follows existing deletion/retention. No account, delivery, renewal or transferable entitlement is created. Quiet information/privacy surfaces explain illustrative report/social fixtures and local-only email use.

## Client presentation and persistence

A deterministic next ordinary screen can be displayed while its predecessor saves, with its input locked until the write is confirmed. Report generation, processing/email saves, mock unlock, upsell and final state still navigate after server confirmation. A failed write returns to the submitted step and retains its exact answer for identical retry; refresh restores only server-confirmed progress. Static illustrations preload/decode ahead and do not imply exposure or unlock. If an image is unavailable, the current composition stays intact and a retry is offered rather than inserting late artwork into the next question. Captured preview exposures stay in a small memory-only metadata outbox until the screen becomes eligible in confirmed server state; answer writes take priority over dispatch.
